# Shipping Service — Testing

## Overview

This document describes the unit and integration tests for the shipping-service,
covering service layer, messaging layer, scheduler, and controller.

---

## Unit Tests

---

### ShipmentServiceImplTest

**Location:**
`src/test/java/com/rabbitmqoutbox/shippingservice/service/impl/ShipmentServiceImplTest.java`

**Framework:** JUnit 5 · Mockito · AssertJ · ArgumentCaptor

**Approach:** `ShipmentRepository` and `OutboxEventService` are mocked. `ShipmentMapper` uses
the real `ShipmentMapperImpl` generated by MapStruct to verify mapping correctness.
`ArgumentCaptor` is used to capture and assert the saved shipment entity in `testScheduleShipmentSuccess`
and the outbox event payload in all state-change methods.

#### Schedule Shipment Tests

| Test | Description |
|---|---|
| `testScheduleShipmentSuccess` | Schedules shipment on `StockReservedEvent` — verifies entity fields, `SCHEDULED` status, `scheduledAt` populated, and `SHIPMENT_SCHEDULED` outbox event published with correct data |

#### Dispatch Shipment Tests

| Test | Description |
|---|---|
| `testDispatchSuccess` | Dispatches shipment — verifies status set to `OUT_FOR_DELIVERY`, `dispatchedAt` populated, and `SHIPMENT_OUT_FOR_DELIVERY` outbox event published with `dispatchedAt` |
| `testDispatchNotFound` | Throws `ShipmentNotFoundException` — verifies repository and outbox never called |
| `testDispatchInvalidStatus` | Throws `IllegalStateException` when shipment is not `SCHEDULED` |

#### Deliver Shipment Tests

| Test | Description |
|---|---|
| `testDeliverSuccess` | Delivers shipment — verifies status set to `DELIVERED`, `deliveredAt` populated, and `SHIPMENT_DELIVERED` outbox event published with `deliveredAt` |
| `testDeliverNotFound` | Throws `ShipmentNotFoundException` |
| `testDeliverInvalidStatus` | Throws `IllegalStateException` when shipment is not `OUT_FOR_DELIVERY` |

#### Fail Shipment Tests

| Test | Description |
|---|---|
| `testFailSuccess` | Fails shipment — verifies status set to `FAILED`, `failedAt` populated, and `SHIPMENT_FAILED` outbox event published with `failureReason` and `failedAt` |
| `testFailNotFound` | Throws `ShipmentNotFoundException` |
| `testFailDeliveredShipment` | Throws `IllegalStateException` when shipment is `DELIVERED` |
| `testFailAlreadyFailed` | Throws `IllegalStateException` when shipment is already `FAILED` |

#### Cancel Shipment Tests

| Test | Description |
|---|---|
| `testCancelSuccess` | Cancels shipment — verifies status set to `CANCELLED`, `cancelledAt` populated, no outbox event published |
| `testCancelNotFound` | Throws `ShipmentNotFoundException` |
| `testCancelDeliveredShipment` | Throws `IllegalStateException` when shipment is `DELIVERED` |
| `testCancelAlreadyCancelled` | Returns early without saving when shipment is already `CANCELLED` |

#### Get Shipment Tests

| Test | Description |
|---|---|
| `testGetByIdSuccess` | Returns correct shipment response by id |
| `testGetByIdNotFound` | Throws `ShipmentNotFoundException` |
| `testGetAllSuccess` | Returns list of all shipments correctly mapped |
| `testGetAllEmpty` | Returns empty list when no shipments exist |

## Integration Tests — ShipmentControllerIT

**Location:**
`src/test/java/com/rabbitmqoutbox/shippingservice/controller/ShipmentControllerIT.java`

**Framework:** JUnit 5 · Spring Boot Test · MockMvc · Testcontainers · AssertJ

**Infrastructure:** PostgreSQL 16 Alpine and RabbitMQ 3 containers via Testcontainers.
Database is recreated fresh for each test run using `ddl-auto: create-drop`.
Each test starts with a clean state via `outboxEventRepository.deleteAll()` and
`shipmentRepository.deleteAll()` in `@BeforeEach`.

**Note:** `OutboxEventRepository` is also injected and cleaned between tests to verify
that outbox events are correctly created alongside shipment state changes.

### PATCH /api/v1/shipments/{id}/dispatch — Dispatch Tests

| Test | Description |
|---|---|
| `testDispatchSuccess` | Dispatches `SCHEDULED` shipment — verifies HTTP 200, status `OUT_FOR_DELIVERY`, `dispatchedAt` populated, and `SHIPMENT_OUT_FOR_DELIVERY` outbox event created |
| `testDispatchNotFound` | Returns HTTP 404 with `SHIPMENT_NOT_FOUND` code |
| `testDispatchInvalidStatus` | Returns HTTP 409 with `INVALID_SHIPMENT_STATE` code when shipment is not `SCHEDULED` |

### PATCH /api/v1/shipments/{id}/deliver — Deliver Tests

| Test | Description |
|---|---|
| `testDeliverSuccess` | Delivers `OUT_FOR_DELIVERY` shipment — verifies HTTP 200, status `DELIVERED`, `deliveredAt` populated, and `SHIPMENT_DELIVERED` outbox event created |
| `testDeliverNotFound` | Returns HTTP 404 with `SHIPMENT_NOT_FOUND` code |
| `testDeliverInvalidStatus` | Returns HTTP 409 with `INVALID_SHIPMENT_STATE` code when shipment is not `OUT_FOR_DELIVERY` |

### PATCH /api/v1/shipments/{id}/fail — Fail Tests

| Test | Description |
|---|---|
| `testFailSuccess` | Fails shipment — verifies HTTP 200, status `FAILED`, `failedAt` populated, and `SHIPMENT_FAILED` outbox event created |
| `testFailNotFound` | Returns HTTP 404 with `SHIPMENT_NOT_FOUND` code |
| `testFailDeliveredShipment` | Returns HTTP 409 with `INVALID_SHIPMENT_STATE` code when shipment is `DELIVERED` |
| `testFailMissingReason` | Returns HTTP 400 when `failureReason` is missing from request body |

### GET /api/v1/shipments/{id} — Get By Id Tests

| Test | Description |
|---|---|
| `testGetByIdSuccess` | Returns HTTP 200 with correct shipment data and all fields populated |
| `testGetByIdNotFound` | Returns HTTP 404 with `SHIPMENT_NOT_FOUND` code |

### GET /api/v1/shipments — Get All Tests

| Test | Description |
|---|---|

## Running the Tests

Run all tests:
```bash
mvn clean test
```

Run specific unit test class:
```bash
mvn clean test -Dtest=ShipmentServiceImplTest
mvn clean test -Dtest=OutboxEventServiceImplTest
mvn clean test -Dtest=OutboxSchedulerTest
mvn clean test -Dtest=OutboxEventPublisherImplTest
mvn clean test -Dtest=StockEventConsumerTest
mvn clean test -Dtest=OrderEventConsumerTest
```

Run integration tests only:
```bash
mvn clean test -Dtest=ShipmentControllerIT
```

> Docker must be running for integration tests — Testcontainers requires it to start
> the PostgreSQL and RabbitMQ containers.
