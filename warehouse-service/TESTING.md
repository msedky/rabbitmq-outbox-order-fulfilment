# Warehouse Service — Testing

## Overview

This document describes the unit and integration tests for the warehouse-service,
covering `StockServiceImpl` (unit tests) and `StockController` (integration tests).

---

## Unit Tests — StockServiceImplTest

**Location:**
`src/test/java/com/rabbitmqoutbox/warehouseservice/service/impl/StockServiceImplTest.java`

**Framework:** JUnit 5 · Mockito · AssertJ

**Approach:** Repositories and `OutboxEventService` are mocked. `StockMapper` uses
the real `StockMapperImpl` generated by MapStruct to verify mapping correctness.

---

### Create Stock Tests

| Test | Description |
|---|---|
| `testCreateStockSuccess` | Creates stock with valid input — verifies all response fields and repository save call |
| `testCreateStockWithZeroQuantity` | Creates stock with zero available quantity — verifies zero is handled correctly |

---

### Get All Stocks Tests

| Test | Description |
|---|---|
| `testGetAllStocksSuccess` | Returns multiple stocks — verifies size, productIds, and quantities |
| `testGetAllStocksEmpty` | Returns empty list when no stocks exist |

---

### Reserve Stock Tests

| Test | Description |
|---|---|
| `testReserveStockSuccessWithSingleItem` | Reserves stock for a single item — verifies quantity adjustments, reservation creation, and outbox event |
| `testReserveStockSuccessWithMultipleItems` | Reserves stock for 3 items — verifies each product is processed correctly |
| `testReserveStockInsufficientQuantity` | Throws `InsufficientStockException` when requested quantity exceeds available |
| `testReserveStockNotFound` | Throws `StockNotFoundException` when product does not exist |

---

### Release Stock Tests

| Test | Description |
|---|---|
| `testReleaseStockSuccess` | Releases reserved stock — verifies quantities restored and status changed to `RELEASED` |
| `testReleaseStockNoReservationsFound` | Handles gracefully when no `RESERVED` reservations found for order |
| `testReleaseStockMultipleItems` | Releases 2 reservations — verifies both processed |
| `testReleaseStockSuccessWithMultipleItems` | Releases 3 reservations — verifies each product's quantities restored correctly |
| `testReleaseStockStockNotFound` | Throws `StockNotFoundException` when stock entity not found during release |

---

### Fulfill Stock Tests

| Test | Description |
|---|---|
| `testFulfillStockSuccess` | Marks reservation as `FULFILLED` on shipment delivery |
| `testFulfillStockNoReservationsFound` | Handles gracefully when no `RESERVED` reservations found for order |
| `testFulfillStockMultipleItems` | Fulfills 2 reservations — verifies both saved with `FULFILLED` status |

---

## Integration Tests — StockControllerIT

**Location:**
`src/test/java/com/rabbitmqoutbox/warehouseservice/controller/StockControllerIT.java`

**Framework:** JUnit 5 · Spring Boot Test · MockMvc · Testcontainers · AssertJ · Hamcrest

**Infrastructure:** PostgreSQL 16 Alpine and RabbitMQ 3 containers via Testcontainers.
Database is recreated fresh for each test run using `ddl-auto: create-drop`.
Each test starts with a clean state via `stockRepository.deleteAll()` in `@BeforeEach`.

---

### POST /api/v1/stocks — Create Stock Tests

| Test | Description |
|---|---|
| `testCreateStockSuccess` | Creates stock with valid request — verifies HTTP 201, full response fields, and DB persistence via `stockRepository.findByProductId()` |
| `testCreateStockDuplicateProductId` | Returns HTTP 400 with `DUPLICATE_ENTRY` code when `productId` already exists |
| `testCreateStockWithZeroQuantity` | Creates stock with zero quantity — verifies HTTP 201 and DB persistence |
| `testCreateStockWithLargeQuantity` | Creates stock with quantity 999999 — verifies HTTP 201 and DB persistence |
| `testCreateStockMissingProductId` | Returns HTTP 400 when `productId` is blank |
| `testCreateStockMissingProductName` | Returns HTTP 400 when `productName` is blank |
| `testCreateStockMissingQuantity` | Returns HTTP 400 when `availableQuantity` is missing from request body |
| `testCreateStockNegativeQuantity` | Returns HTTP 400 when `availableQuantity` is negative |
| `testCreateStockInvalidJson` | Returns HTTP 400 when request body is malformed JSON |
| `testCreateStockMissingContentType` | Returns HTTP 415 when `Content-Type` header is missing |

---

### GET /api/v1/stocks — Get All Stocks Tests

| Test | Description |
|---|---|
| `testGetAllStocksEmpty` | Returns HTTP 200 with empty array when no stocks exist |
| `testGetAllStocksSuccess` | Returns HTTP 200 with all stocks — verifies size, all response fields for each item, and DB persistence for each returned stock |

## API Response Structure

### Success (200 / 201)
```json
{
  "success": true,
  "data": {
    "stockId": "uuid",
    "productId": "string",
    "productName": "string",
    "availableQuantity": 100,
    "reservedQuantity": 0,
    "createdAt": "2026-04-24T10:00:00Z",
    "updatedAt": "2026-04-24T10:00:00Z"
  },
  "error": null
}
```

### Error (400 / 415 / 500)
```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "error details",
    "timestamp": "2026-04-24T10:00:00Z"
  }
}
```

## Running the Tests

Run all tests:
```bash
mvn clean test
```

Run unit tests only:
```bash
mvn clean test -Dtest=StockServiceImplTest
```

Run integration tests only:
```bash
mvn clean test -Dtest=StockControllerIT
```

> Docker must be running for integration tests — Testcontainers requires it to start
> the PostgreSQL and RabbitMQ containers.
