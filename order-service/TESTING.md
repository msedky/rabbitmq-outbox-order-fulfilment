# Order Service — Testing

## Overview

This document describes the unit and integration tests for the order-service,
covering service layer, messaging layer, scheduler, and controller.

---

## Unit Tests

---

### OrderServiceImplTest

**Location:**
`src/test/java/com/rabbitmqoutbox/orderservice/service/impl/OrderServiceImplTest.java`

**Framework:** JUnit 5 · Mockito · AssertJ · ArgumentCaptor

**Approach:** `OrderRepository` and `OutboxEventService` are mocked. `OrderMapper` uses
the real `OrderMapperImpl` generated by MapStruct to verify mapping correctness.
`ArgumentCaptor` is used to capture and assert the saved entity and outbox event
in `testCreateOrderSuccess` and `testCancelOrderSuccess` since both are built inside the method.

#### Create Order Tests

| Test | Description |
|---|---|
| `testCreateOrderSuccess` | Creates order with valid request — verifies all entity fields, total amount calculation, items mapping, and `ORDER_PLACED` outbox event published with correct data |

#### Cancel Order Tests

| Test | Description |
|---|---|
| `testCancelOrderSuccess` | Cancels `PENDING` order — verifies status set to `CANCELLED`, `cancelledAt` populated, and `ORDER_CANCELLED` outbox event published with correct data |
| `testCancelOrderNotFound` | Throws `OrderNotFoundException` — verifies repository and outbox never called |
| `testCancelOrderAlreadyCancelled` | Throws `IllegalStateException` when order is already `CANCELLED` |
| `testCancelOrderDelivered` | Throws `IllegalStateException` when order is `DELIVERED` |
| `testCancelOrderOutForDelivery` | Throws `IllegalStateException` when order is `OUT_FOR_DELIVERY` |
| `testCancelOrderFailed` | Throws `IllegalStateException` when order is `FAILED` |

#### Confirm Order Tests

| Test | Description |
|---|---|
| `testConfirmOrderSuccess` | Marks order as `CONFIRMED` with `confirmedAt` populated on `StockReservedEvent` |
| `testConfirmOrderNotFound` | Throws `OrderNotFoundException` |

#### Mark As Shipped Tests

| Test | Description |
|---|---|
| `testMarkAsShippedSuccess` | Marks order as `SHIPPED` with `shippedAt` populated on `ShipmentScheduledEvent` |
| `testMarkAsShippedNotFound` | Throws `OrderNotFoundException` |

#### Mark As Out For Delivery Tests

#### Mark As Delivered Tests

## Integration Tests — OrderControllerIT

**Location:**
`src/test/java/com/rabbitmqoutbox/orderservice/controller/OrderControllerIT.java`

**Framework:** JUnit 5 · Spring Boot Test · MockMvc · Testcontainers · AssertJ

**Infrastructure:** PostgreSQL 16 Alpine and RabbitMQ 3 containers via Testcontainers.
Database uses `ddl-auto: update`. Each test starts with a clean state via
`outboxEventRepository.deleteAll()` and `orderRepository.deleteAll()` in `@BeforeEach`.

**Note:** `OutboxEventRepository` is also injected and cleaned between tests to verify
that outbox events are correctly created alongside order state changes.

### POST /api/v1/orders — Create Order Tests

| Test | Description |
|---|---|
| `testCreateOrderSuccess` | Creates order with valid request — verifies HTTP 201, order persisted in DB, and `ORDER_PLACED` outbox event created with `PENDING` status |
| `testCreateOrderValidationFailure` | Returns HTTP 400 with `VALIDATION_ERROR` code when request body is empty |

### PATCH /api/v1/orders/{id}/cancel — Cancel Order Tests

| Test | Description |
|---|---|
| `testCancelOrderSuccess` | Cancels `PENDING` order — verifies HTTP 200, status updated to `CANCELLED` in DB, and `ORDER_CANCELLED` outbox event created |
| `testCancelOrderNotFound` | Returns HTTP 404 with `ORDER_NOT_FOUND` code |
| `testCancelOrderInvalidState` | Returns HTTP 409 with `INVALID_ORDER_STATE` code when order is `DELIVERED` |

### GET /api/v1/orders/{id} — Get Order By Id Tests

| Test | Description |
|---|---|
| `testGetByIdSuccess` | Returns HTTP 200 with correct order data |
| `testGetByIdNotFound` | Returns HTTP 404 with `ORDER_NOT_FOUND` code |

### GET /api/v1/orders — Get All Orders Tests

| Test | Description |
|---|---|
| `testGetAllSuccess` | Returns HTTP 200 with list of 2 orders |
| `testGetAllEmpty` | Returns HTTP 200 with empty list |


## Running the Tests

Run all tests:
```bash
mvn clean test
```

Run specific unit test class:
```bash
mvn clean test -Dtest=OrderServiceImplTest
mvn clean test -Dtest=OutboxEventServiceImplTest
mvn clean test -Dtest=OutboxSchedulerTest
mvn clean test -Dtest=OutboxEventPublisherImplTest
mvn clean test -Dtest=OrderEventConsumerTest
```

Run integration tests only:
```bash
mvn clean test -Dtest=OrderControllerIT
```

> Docker must be running for integration tests — Testcontainers requires it to start
> the PostgreSQL and RabbitMQ containers.
